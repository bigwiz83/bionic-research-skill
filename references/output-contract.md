# 출력 계약 v1.0.0

패키지 v0.3.0의 개별 실행은 [개별 구조화 계약](individual-structure.md)을 함께 따른다. 여기의 원천 추출 계약은 그대로 유지하며 집단 비교·채점·전략 도구는 개별 실행 범위에서 제외한다. 아래 v0.2.0 비교 계약 안내는 별도 후속 분석의 호환성 설명이다.

패키지 v0.2.0의 그룹·결과 비교는 별도의 [cohort-contract.json](../schemas/cohort-contract.json)과 [그룹·요인 분석 안내](cohort-analysis.md)를 따른다. 아래 v1.0.0 계약은 기존 추출 모듈 v0.1.0의 intake/출력 규칙이며 비교 모듈의 research 파생 출력 지원과 구별한다.

기계 판독 계약은 [schemas/contract.json](../schemas/contract.json)의 `$defs`에 있다. 분류 기준은 `instruction-patterns-0.1.0`, 스킬 버전은 `0.1.0`이다. `scripts/build_contract.py`가 스키마 원본이며 배포 JSON과 일치하는지 시험한다. 실행기는 스키마에 사용된 제한된 JSON Schema 키워드를 검사하는 표준 라이브러리 구현이다. 임의의 JSON Schema를 검증하는 범용 라이브러리가 아니다.

v0.5.2의 정규화 intake는 `data_mode=synthetic`과 `research`를 지원한다. namespace는 SYN- 또는 DS- 코드를 사용한다. 모드는 자료 출처 표시이며 자료 유형을 근거로 분석을 차단하지 않는다. 개발 검사는 생성한 가상 기록으로 두 모드를 검증했다.

## 내부 intake

`manifest.json`은 가명 참여자/과제, 고정 데이터셋 namespace, 요청 세션 전체 목록, 접근 승인, 시도 상태, 원기록 총량 확인 범위, 분석 경계, 실제 모델 설정 확인 범위를 담는다. `events_file`은 manifest와 같은 intake 폴더 내부의 파일만 허용한다. 절대 경로·상위 경로·폴더 밖 symlink/junction을 거부한다. 분석용·미승인·접근불가 세션의 파일은 열지 않는다.

세션 파일은 공개 사건 배열이다. `source_index`는 intake 내 참조 번호, `source_sequence`와 `source_id`는 실제 반환된 경우만 넣고 없으면 null이다. `timestamp`는 원기록에 있는 timezone 포함 시각만 넣고 없으면 null이다. `text`에는 실제 읽은 본문만 담는다. 비공개 사고 과정은 수집하지 않는다. private 합성 반례는 제외 규칙을 시험하기 위해서만 있다.

`codings.json`은 분류 작업자가 만든 초안이다. 포함된 고유 사용자 사건마다 정확히 한 항목이 필요하다. AI·도구 사건은 코딩 항목을 만들지 않는다. `categories`는 복수 가능, `criterion_codes`는 기준표와 일치해야 한다. 자유 원문 인용·자유 사유·추정 시각 같은 추가 필드는 거부한다.

`evidence`의 `start/end`는 정규화 문자열의 Python Unicode code point 기준 `[start,end)`다. 적어도 자기 사용자 발화의 실제 읽은 문자열을 근거로 삼는다. `related_refs`는 실제 읽은 공개 과제 사건만 연결한다. 길이가 0인 사용자 발화는 현재 코딩 계약으로 증거 범위를 만들 수 없으므로 실패/누락 처리 뒤 어댑터 개선이 필요하다.

디스크의 파일 전체 로드와 분류 모델이 화면/도구 반환에서 실제 본문을 읽은 범위는 다를 수 있다. 실행기의 `read_ranges`는 제공한 정규화 intake를 스크립트가 읽은 행 범위다. 모델에게 반환된 본문이 잘렸다면 원본 파일의 완전성 표시를 그대로 사용하지 않고 **별도 평가용 intake**에 실제 읽은 발췌와 `content_complete=false`, 문자 범위 영수증을 저장한다. 모델이 읽지 않은 본문을 근거로 삼거나 스크립트의 전체 로드를 모델의 의미 해석 완료로 표시하지 않는다.

## 실행별 출력

| 파일 | 의미 |
|---|---|
| `actions.csv` | 고유 공개 과제 사건, 가명 ID, 주체, 관찰 요약, 분류, 판단 상태, 내부 출처, 확인된 시각, 근거·맥락 참조 |
| `patterns.json` | actions와 기준 버전, 잠정 분류별 사건 수·분모·비율·근거 ID, 보류/미분류 |
| `coverage.json` | 요청/읽은 세션·행 범위·누락·잘림·제외·중복, 모델 확인 범위, 입력·구현·기준·스킬·계약 해시, 실행 ID, 연구용 초안 상태 |
| `report.md` | 검토용 범위·집계·한계 |
| `integrity.json` | 위 네 파일의 SHA256. 우발적 변경 검사용이며 서명·접근통제가 아님 |
| `failure.json` | 실패한 실행의 코드와 ID. 실패본을 정상 결과로 합산하지 않음 |

CSV의 배열 셀은 JSON 문자열이며 UTF-8 BOM을 사용한다. null 시각/원본 순번은 빈 셀이다. JSON에는 null을 유지한다. 관찰 요약은 고정 기준 문구로 만들고 원문·원본 ID를 복사하지 않는다. 고정 코드의 판단 의미와 evidence span이 판단 근거를 구성한다. 상세 원문 대조는 지정 intake를 근거로 한다. SHA256과 가명화된 ID도 검토 대상이며 안전한 익명화를 보증하지 않는다.

`complete_extraction=true`는 요청한 모든 과제 세션의 공개 범위에 대해 알려진 전체량, 모든 정규화 행, 끝 확인 영수증, 본문 완전성 조건이 충족됨을 뜻한다. 비공개·compaction·분석 경계 뒤의 정책 제외는 별도로 남긴다. 원기록의 진위·외부 앱 조작·바이오닉 수집 기능의 완전성을 검증하는 값이 아니다. 전체량을 모르면 누락 범위가 []여도 partial이다.

## 중복과 재실행

`event_id`는 고정 namespace + 세션 가명 + 원본 ID가 실제 있을 경우 그 ID의 해시, 없으면 고정 intake 행 번호의 해시다. 원본 ID를 만들어내지 않는다. 같은 원본 ID·같은 내용의 복원 중복만 병합한다. 같은 문구라도 다른 원본 ID/행의 실제 반복은 별개 사건이다. 원본 ID 충돌이 있으면 실패한다.

원본 ID가 없는 경우 intake 행 번호를 재정렬/재부여하면 실행 간 같은 사건의 식별을 보장할 수 없다. namespace와 intake 번호 대응표를 고정해서 사용한다. 다른 과제·참여자 자료에는 다른 namespace를 준다. ID가 있는 사건도 참조 범위/내용/코딩이 달라지면 aggregate에서 불일치로 보존한다.

재실행은 항상 새로운 `run-UTC-UUID` 폴더를 만든다. `aggregate`는 같은 event_id의 완전히 동일한 행을 한 번만 세고, 코딩·근거·메타데이터가 다르면 모든 변형을 `conflicts`에 남겨 집계 분모에서 보류한다. 여러 실행의 읽은 범위가 합쳐져 완전 추출이라고 자동 판단하지 않는다. 사람의 변경·합의 기록과 확정본 저장 UI는 후속 개발 대상이다.

입력은 변경하지 않는 사후 스냅샷으로 보관한다. validate는 현재 패키지와 원기록으로 다시 산출해 비교하므로 구현·계약·기준이 바뀌면 같은 실행이라고 승인하지 않는다. 이전 실행을 검증하려면 그 실행이 사용한 버전 패키지를 함께 보관한다. 개발 도중 만들어진 중간 실행과 최종 배포판의 실행은 구분한다.
