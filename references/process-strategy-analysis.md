# 지시 모듈·과정 비교와 인터벤션 전략 — v0.3.0

이 문서는 **연구진의 별도 후속 분석 도구** 안내다. 개별 참여자가 실행하는 추출 스킬은 [individual-structure.md](individual-structure.md)에 따라 정보 추출·구조화만 수행하며 집단 비교/채점/전략 개발을 호출하지 않는다. 패키지에 들어 있는 후속 지원 도구와 스킬 실행 범위를 구분한다.

연구 목적은 참여자의 사용자 지시를 재사용 가능한 행동 모듈로 구조화하고, 그 조합·순서·반복·AI/도구 사건과의 관찰 연결을 비교하는 것이다. 정답이 정의된 과제에서는 자동 판정한 정답·근접·오답과 과정을 연결해 인터벤션 전략을 개발한다. 전략의 효과는 새로운 참여자로 별도 검증해야 한다. 사람의 성향 유형을 진단하거나 좋은 프롬프트 점수를 매기는 도구가 아니다.

## 1. 개별 추출 결과만으로 모듈과 과정을 비교

지정한 결과 폴더의 기존 actions.csv/patterns.json/coverage.json/report.md/integrity.json만 읽는다. 배정표·성과 평가표·정답지·수동 comparison-plan.json은 필요 없다. 참여자·과제·세션·패턴·근거·확인된 모델 설정을 추출 결과에서 가져온다. 참여자나 과제 식별자가 모호하면 추정으로 합치지 않는다.

```powershell
& $pythonExe "$packageRoot\scripts\cohort.py" --runs $runA $runB --out-root "$packageRoot\runs"
```

또는 compare_processes.py를 직접 실행한다. 기존 cohort.py --plan 명령은 외부 평가값이 이미 있는 별도 확장이다.

- **행동 모듈:** 사용자 발화 한 건의 분류 묶음 + 다음 관찰 사용자 발화 전까지 기록된 AI·도구 사건. 실제 지시 수행의 시작/끝이나 원인 연결을 확정한 경계는 아니다. 첫 사용자 발화 전 사건은 미연결 초기 사건으로 보존한다.
- **동시 분류:** 목표 명시와 검증 요청이 같은 발화에 있으면 하나의 묶음이다. 두 분류 사이에 가상의 순서를 만들지 않는다.
- **세션 과정:** 관찰된 모듈의 순서·인접 전환·반복·2~3모듈 반복 조각이다. 다른 세션을 임의로 잇지 않는다. 실제 원본 순번이 없으면 normalized_package_order로 표시한다. 경과시간이나 사용자 이해 시간은 만들지 않는다.
- **그룹:** 같은 과제의 관찰 패턴 조합과 동일 모듈 순서를 자동으로 묶는다. 같은 조합이라도 순서가 다르면 구분한다. 불완전/보류/미분류 범위를 드러내며 안정된 성향 또는 검증된 통계 군집으로 소개하지 않는다.
- **과정 대조:** 같은 task_id의 다른 참여자 과정에 삽입·삭제·교체를 정렬하고 사건 근거를 연결한다. 편집 거리는 순서 차이이며 성과·능력 점수가 아니다. 같은 task_id가 같은 과제 정의라는 사실을 독립 검증하지 않는다. 최대 쌍 수 기본 500, --max-process-pairs로 변경 가능하며 생략 쌍을 표시한다.

출력: processes.json(모듈/순서/그룹/위치별 대조), modules.csv, transitions.csv, features.csv, report.md, integrity.json. comparison-inputs.json은 선택한 출처와 ID를 프로그램이 자동 작성한 영수증이며 사용자가 작성할 입력 계획이 아니다. 초안 코딩은 자동으로 reviewed로 바꾸지 않는다. 소스 완전성·도구 실패·사건 수도 관찰 지표이지 성과 점수는 아니다.

## 2. 정답을 한 번 등록하고 건수 결과를 자동 판정

연구진은 과제별 **정답 기준**을 한 번 등록한다. 이미 연구 앱/과제 정의에 정답이 있다면 승인된 숫자 기준을 연결하면 된다. 참여자별 점수표나 별도 배정표는 작성하지 않는다. 현재 독립 패키지는 연구 앱에서 정답을 자동 가져오는 연동을 구현하지 않았다. 과제 수행 중 정답 기준이나 패턴 평가를 참여자에게 노출하지 않는다.

현재 구현은 **비음수 정수 집계 건수**만 지원한다. 예를 들어 정해진 포함/제외·집계 단위·대상 범위에 따른 건수 정답은 해당 기준이 고정됐을 때 대조할 수 있다. 이 후속 도구는 기록된 결과값과 제공된 정답 기준을 대조한다. 비율·문서·코드의 의미·루브릭 채점은 후속 확장이다.

등록 파일의 가상 예시:

```json
{
  "answer_key_version": "1.0.0",
  "answer_key_id": "SYN-COUNT-KEY-1",
  "tasks": [{
    "task_id": "T-SYN-COUNT",
    "metrics": [{
      "metric_id": "TARGET_COUNT", "expected": 10,
      "near_tolerance": 1, "weight": 1, "error_scale": 10
    }]
  }]
}
```

expected=10은 완전히 만든 가상 시험값이다. 실제 정답이나 임상 기준을 뜻하지 않는다. 근접 범위·weight·error_scale은 사전에 연구진이 등록한다. 결과를 본 뒤 특정 전략에 유리하게 바꾸지 않는다.

## 3. 추출 시 최종 숫자 결과도 구조화

기존 네 추출 파일은 행동 분류이며 최종 집계값이 포함되지 않는다. 정답 판정을 요청하면 승인된 과제 제출 결과에서 확인된 집계값을 **task-result.json**으로 함께 정규화한다. 이것은 사람이 따로 점수표를 만드는 단계가 아니다. 숫자를 원문에서 확인 못하면 null/누락으로 남긴다. 추출 모델이 원자료를 다시 집계하거나 AI의 성공 진술을 정답으로 바꾸지 않는다.

```json
{
  "result_schema_version": "1.0.0",
  "result_id": "R-SYN001",
  "participant_id": "P-SYN001",
  "task_id": "T-SYN-COUNT",
  "values": {"TARGET_COUNT": 10},
  "pre_feedback_window": {
    "receipt_ref": "SYN-BEFORE-ANSWER-FEEDBACK",
    "cutoffs": [{
      "dataset_namespace": "SYN-PROCESS-001",
      "session_id": "S-SYN-01", "max_source_index": 12
    }]
  }
}
```

가상 숫자·ID·구간은 실제 관찰 값으로 바꾼다. 최종 제출 결과가 어느 기록인지 내부 result_id/receipt 대응 근거를 보존한다. 최종 결과가 여러 버전으로 충돌하면 자동으로 고르지 않고 분석을 중단한다. 같은 재추출 결과는 중복 처리하지 않는다.

pre_feedback_window는 **정답 피드백을 받기 전** 행동 구간의 package source_index 상한이다. 단위의 모든 과제 세션/namespace를 명시하고 제외 구간은 상한 0으로 둔다. 피드백 경계 근거가 없으면 null이다. 이 값은 사용자가 임의로 붙이는 시간이나 독립 검증된 원본 시각이 아니다. 승인된 기록/제출 연계에서 근거를 확인해야 한다. 피드백 후 학습 발화는 전략 발견의 근거에 섞지 않는다. 경계가 없으면 전체 관찰 과정으로만 비교하고 전략 초안의 근거에서는 제외한다.

task-result.json의 숫자와 정답 기준을 대조하는 계산기는 구현했다. 바이오닉이 실제 최종 제출 파일에서 정확히 이 필드를 추출하는 원천 어댑터/도구 계약과 기존 앱 자동 제출 연동은 아직 검증하지 않았다. 스킬 지침만으로 실제 숫자 추출 정확성을 보장하지 않는다.

## 4. 자동 판정 → 정답 과정 역추적 → 전략 초안

```powershell
& $pythonExe "$packageRoot\scripts\grade_and_trace.py" --runs $runA $runB --answer-key $answerKey --out-root "$packageRoot\runs"
```

모든 지표가 정확히 같으면 correct, 정확히 같지는 않지만 모든 오차가 등록된 near_tolerance 이하면 near, 하나라도 넘으면 incorrect다. 값/기준이 없으면 unavailable이며 0점이나 오답으로 대체하지 않는다. 형식에 없는 지표·음수·소수 건수는 거부한다. 여러 지표는 등록 weight로 결합한다.

근접 점수는 각 지표의 `100 × max(0, 1 − 절대오차 / error_scale)`를 weight로 평균한다. 이는 등록한 점수식의 숫자 근접도이며 사람의 실력·이해도·임상 판단력 점수가 아니다. 정답/근접 범주는 near_tolerance로, 근접 점수는 error_scale로 각각 계산하므로 두 값의 의미를 함께 표시한다.

출력:

- grades.csv: 자동 판정·근접 점수·지표별 제출값/정답/오차.
- graded-processes.json: 자동 판정, 판정 그룹의 패턴 분포, 정답 피드백 전 과정, 전체 모듈·정렬·출처·제한.
- intervention-strategies.json: **전략** ID, 관찰 모듈 순서, 단계별 지시 틀·동시 묶음·오류 시 조건 분기, 적용 조건, 검증 가설, 근거 과정, 같은 과정의 정답/근접/오답 관찰 수.
- report.md, integrity.json: 검토 설명과 해시.

전략은 정답·근접, 피드백 전 경계, 완전한 관찰 코딩 과정에서 발견한 **초안**이다. 분류 사전의 추상 지시 틀을 순서대로 구성한 것으로 원문 성공 프롬프트의 복제가 아니다. 오류 교정은 오류가 관찰됐을 때만 적용하는 조건 분기이며 일부러 오류를 만들라는 지시가 아니다. 같은 순서가 오답에서도 관찰됐는지, 부분 과정 포함/완전 과정만의 근거 수를 구분한다.

전략 제공이 정확성·근접도를 개선하는지는 아직 검증하지 않았다. 새 참여자 적용에서는 전략 지시 내용과 노출 시점, 과제·정답 기준, 비교 조건, 결과/코딩 평가 절차를 사전에 정하고 전략 개발에 사용하지 않은 참여자로 재현성을 검증해야 한다. 현재 도구는 사람에게 전략을 자동 배정하거나 시행하지 않는다.

## 검증과 적용 범위

개발 시험은 생성한 가상 과제·집계값·정답으로 수행했다. 이 후속 분석 도구는 지정한 추출 산출물을 입력으로 사용한다. 숫자 대조, 순서 정렬, 초안 전략의 일관성과 파일 읽기 범위 검증은 행동 분류의 의미적 정확성이나 전략 효과를 증명하지 않는다. 과제별 정답 기준의 정확성과 원천 결과 추출은 별도 확인한다.
