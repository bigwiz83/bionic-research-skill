# 그룹·결과 비교 모듈 v0.2.0

v0.3.0에서 이 문서는 **외부 평가값을 사용하는 선택 확장**이다. 기본 목적의 모듈·순서·과정 비교와 자동 정답 기반 전략 개발은 [process-strategy-analysis.md](process-strategy-analysis.md)를 따른다. 배정표·참여자별 점수표·수동 비교 계획은 기본 분석에 요구하지 않는다.

이 모듈은 승인된 **파생 추출 결과**를 합쳐 관찰 패턴, 그룹별 결과 차이, 결과와 함께 관찰된 후보 요인을 분석한다. 합성 시험에만 묶인 분석기는 아니다. `data_mode=research`도 지원한다. 개발 AI는 실자료를 열지 않고 생성 합성 자료만 시험한다. 원기록 수집·기관 반출·실제 바이오닉 설치는 별도 절차다.

## 무엇을 더 모아야 하나

한 분석 단위는 참여자×과제다. 재개 세션과 실패한 시도는 같은 단위의 지정 결과 폴더에 포함한다. 새로운 독립 과제 시도는 별도 task_id를 사용한다. 같은 사람의 여러 과제는 같은 가명 participant_id를 유지한다. namespace·세션 가명·내부 행 번호를 재추출마다 바꾸면 중복을 검증할 수 없다.

| 입력 | 필요한 이유 | 모를 때 |
|---|---|---|
| 참여자·과제 ID / 승인된 결과 폴더 목록 | 반복 과제 묶기, 재실행 중복 제거 | 승인을 추정하지 않음 |
| condition_code | 사전 비교 그룹 | null 그룹으로 기술 |
| task_family / difficulty_band | 서로 다른 과제·난이도 구분 | 보정에서 제외 및 누락 수 |
| experience_band / prior_training | 경험과 사전 교육 조건 | null 유지 |
| model_condition | 모델·설정·도구 환경 조건 | null; 출처 모델 설정은 별도로 보존 |
| task_order_band | 반복 시행의 학습·피로 조건 | null 유지 |
| 공통 결과 지표·척도 버전·단위·범위·방향 | 서로 다른 점수의 혼합 방지 | 결과 평균 계산 불가 |
| 별도 평가값·assessment_ref | AI 성공 주장과 실제 결과 분리 | null; 실패나 0점으로 대체 금지 |
| coding_review | 코딩의 검토 여부 | draft는 기술 자료로만 |
| pre_outcome_window / window_ref | 평가 뒤 발화를 예측 요인에 섞지 않기 | 요인 비교에서 제외 |

실패·중단한 과제의 성과가 척도상 0점으로 **평가**되었다면 0을 입력한다. 점수를 확인 못한 실패는 null이다. 선택적으로 성공본만 모으면 선택 편향이 생긴다. 계획의 전체 단위 수와 누락된 성과를 반드시 보고한다.

원본 시각·실제 순번·도구 시작/종료와 연결 ID는 앞으로의 수집 어댑터에서 받아야 한다. 현재 모듈은 모든 시각과 원본 순번이 확인되고 순서가 일관된 세션의 관찰 첫–끝 간격만 계산한다. 사람의 활동 시간, 이해 시간, 클릭 시간, 병렬 도구 실행 시간은 계산하지 않는다. 시각이 없으면 정규화 행 순서의 전이만 남긴다.

## 비교 계획 작성

스키마는 `schemas/cohort-contract.json`의 `cohort_plan`이다. 그룹 수준과 공변량은 원문을 담지 않는 코드다. 자유 텍스트 개인 배경·임상 정보·파일 본문은 입력 필드에 넣지 않는다. 가명 자료가 안전한 익명 자료라는 뜻은 아니다.

최상위 필드:

- `analysis_version: "0.2.0"`, `data_mode: "synthetic"` 또는 `"research"`; `selection_approved: true`는 지정 범위 승인을 기록한 값이며 기술적 권한이나 출처 증명이 아니다.
- `study_id`, `grouping_basis: "pre_analysis"` 또는 `"exploratory"`.
- `outcome_definition`: `metric_code`, `rubric_version`, `unit_code`, `minimum`, `maximum`, `higher_is_better`. 모든 단위가 이 공통 기준으로 평가되었다는 입력자의 확인이 필요하다. 다른 척도는 별도 계획에서 분석한다.
- `group_by`: 코드 필드 목록. `comparisons`: 비교할 `field`, `level_a`, `level_b`를 사전 지정한다. 수많은 조합을 훑어 가장 큰 차이만 골라 결론 내리지 않는다.
- `adjust_by`: 비교할 공통 조건. 그룹 변수 자체는 보정하지 않는다. 모든 변수를 무조건 넣지 않고 결과 이후 변수나 매개 변수를 통제하지 않도록 연구진이 선택한다. task_family·난이도·모델 조건·경험·과제 순서의 불균형을 먼저 점검한다.
- `bootstrap_replicates`(100–10000), `seed`.
- `units`: 아래 형식. run_dirs는 계획 파일 기준 상대 경로 또는 승인된 절대 경로다. 프로그램은 각 폴더의 actions.csv/patterns.json/coverage.json/report.md/integrity.json만 읽으며 source_hashes 경로나 개인 저장소를 따라가지 않는다. 지정 경로의 접근 권한은 실행 환경에서 관리한다.

```json
{
  "unit_id": "U-001",
  "participant_id": "P-001",
  "task_id": "T-001",
  "approved": true,
  "run_dirs": ["derived/run-EXPLICITLY-SELECTED"],
  "coding_review": "reviewed",
  "covariates": {
    "condition_code": "A", "task_family": "FORMAT",
    "difficulty_band": "MEDIUM", "experience_band": null,
    "model_condition": "MODEL-C1", "prior_training": null,
    "task_order_band": "FIRST"
  },
  "outcome": {"value": 80, "reviewed": true, "assessment_ref": "RATING-001"},
  "pre_outcome_window": [{"session_id": "S-001", "max_source_index": 42}],
  "window_ref": "PRE-EVALUATION-001"
}
```

예시의 결과 폴더·점수·구간은 실제 관찰로 바꾼다. 구간 근거가 없으면 pre_outcome_window와 window_ref를 둘 다 null로 둔다. cutoff는 **패키지 내부 source_index**의 상한이며 원본 시간 순서의 증명이 아니다. 단위의 모든 과제 세션을 명시하고 제외할 세션은 0으로 지정한다. window_ref의 평가 선행 여부와 점수 근거는 기관 내부에서 사람이 대조한다. 프로그램은 자료의 진위나 분류 의미를 검증하지 않는다.

기존 추출 출력 계약 v1.0.0을 확장해 파생 coverage의 research 모드와 DS namespace를 비교 모듈에서 허용한다. 실제 연구 원천은 연구 모드로 기록해야 한다. 합성 표시를 실자료 호환을 위해 임의로 바꾸지 않는다. 기존 extract.py의 원기록 intake는 합성 모드이며, 기관의 실자료 정규화 어댑터는 별도 검증 대상이다. 이는 비교 모듈의 research 지원과 구별한다.

## 출력과 해석

- `features.csv`: 단위별 사건 수, 검토·완전성·주 분석 적격, 관찰 비율, 평가 전 비율, 결과값, 공변량, 관찰 패턴 조합. 원문은 넣지 않는다.
- `analysis.json`: 그룹 집계, 지정 비교, 일곱 후보 패턴의 평가 전 관찰 있음/없음 비교, 층별 결과, 민감도 결과, 불확실성, 세션 내 전이·관찰 간격, 출처 해시·모델 설정.
- `report.md`: 사람이 읽는 결과·분모·누락·제외·해석 제한. `integrity.json`: 출력 해시. 오류는 새 실행의 failure.json에 보존한다.

관찰 비율은 본문 완전·coded 사용자 발화만을 분모로 한다. 전체 사용자 발화 수와 불확실 발화 수도 보존한다. 보류·잘림은 행동 없음이 아니다. 주 분석은 모든 지정 결과가 complete이며 코딩 reviewed이고 사용자 발화가 모두 완전·확정 코딩인 단위로 제한한다. 진짜 애매한 발화를 제외하면 선택 편향이 생길 수 있어 이 제한과 민감도 결과를 함께 보고한다. 요인 비교는 여기에 평가 전 사용자 발화가 존재하는 조건을 추가한다.

개인의 과제별 값을 평균한 뒤 참여자별 같은 가중으로 그룹 평균을 계산한다. 말이 많거나 과제가 많은 사람의 발화가 표본 수를 부풀리지 않는다. 반복 참여자는 그룹을 넘나들어도 부트스트랩에서 전체 과제 묶음을 함께 재표집한다. 95% 분위수 구간은 탐색용이며 그룹별 참여자 5명 미만이면 표시하지 않는다. 5명은 화면 표시 기준일 뿐 표본 적정성·검정력의 기준이 아니다. 보정 차이에는 현재 신뢰구간을 계산하지 않는다.

층 보정은 지정 조건 조합마다 두 그룹이 함께 있는 층을 찾아, 각 층 내 참여자 동일 가중 평균 차이를 낸 뒤 **공통 층을 동일 가중**으로 평균한다. 이는 공통 조건 집단의 기술적 차이이며 전체 집단 효과나 인과 효과가 아니다. 공통 층 없음은 확인 불가다. 전체 차이와 보정 차이의 방향 역전을 표시하되 대상 집단과 가중도 달라졌다는 점을 함께 설명한다. `overlap_units`, 층별 참여자 수, 공변량 누락 수를 확인한다.

동일 재추출은 event_id로 중복 제거한다. 코딩 충돌·같은 세션 가명의 다른 행 매핑·기준 해시 혼합은 분석을 중단해 검토한다. 같은 기준 버전이라도 SKILL 해시·모델 설정 차이를 기록하며 변경된 프롬프트/코더에 따른 측정 차이를 점검한다. 해시는 우발적 변경 검사용이고 서명·진위 보증이 아니다.

관찰 패턴 조합 그룹은 해당 과제의 기술적 프로필이다. K-means/잠재계층·안정 성향 유형·검증된 척도는 구현하지 않는다. 조합이 많은 작은 데이터에서 자동 군집이나 회귀 순위를 제시하는 것보다 충분한 표본·코딩 일치·사전 변수 정의가 먼저다. 확인적 회귀/혼합모형/군집 타당화/외부 검증은 별도 분석 계획으로 추가한다. 일곱 후보 비교는 다중 탐색으로 표시하고 유의한 원인 순위를 만들지 않는다.

## 검증 근거와 남은 연구 설계

합성 검증에는 난이도 분포 때문에 전체 평균과 동일 난이도 비교가 반대가 되는 예, 평가 이후 교정, 누락 점수, 반복 과제 가중, 승인 누락, 재추출 충돌, 시각 부재가 포함된다. 산술·계약 검증은 임상·행동 연구 타당성의 검증이 아니다.

인과 요인을 확인하려면 사전 가설, 독립 결과 평가, 조건 배정 또는 설계상 교란 통제, 사전 행동 구간, 표본·검정력 계획, 코딩 신뢰도 검토가 필요하다. 자동으로 원인이라고 이름 붙이지 않는다.

참여자 단위 재표집 근거: [ClusterBootstrap 연구 논문](https://pmc.ncbi.nlm.nih.gov/articles/PMC7148287/). 소수 군집의 한계: [Using Cluster Bootstrapping to Analyze Nested Data With a Few Clusters](https://pmc.ncbi.nlm.nih.gov/articles/PMC5965657/). 이 패키지는 해당 논문의 GLM 또는 R 패키지를 구현한 것이 아니라 그룹 평균 차이에 참여자 단위 재표집 원칙을 적용한다.
